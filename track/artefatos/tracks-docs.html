PRD · o destino

Por que a plataforma precisa de trilhas 4noobs

A comunidade He4rt produz conteúdo open source em repositórios {tema}4noobs no GitHub, mantidos por membros da própria comunidade. Hoje, esse conteúdo é consumido diretamente nos repositórios, sem uma experiência unificada de leitura e descoberta. A proposta é criar uma plataforma que agregue esse conteúdo em uma experiência de leitura focada — listar trilhas, ler aulas e apoiar quem cria — sem rastrear o progresso pessoal de quem lê.


O agregador também serve como base para futuras expansões: curadoria via allowlist, descoberta automática de novos repos e eventos de domínio que outros módulos (como gamificação) poderão escutar — sem que o conteúdo carregue vocabulário de recompensa.

PRD · leg 01
pesquisa · ticket 01

O terreno, medido

9 repos analisados 1 padrão dominante: README como TOC 1º nível = módulos variações em engine e nomenclatura

O mapeamento dos repositórios 4noobs encontrou um padrão comum — README como índice, módulos como diretórios de primeiro nível — mas também variações reais (estruturas de docs, extensões .MD, diretórios Content/) que obrigam o ETL a ser configurável, nunca assumido.

Para autores, o gold standard é o .all-contributorsrc; onde não existe, cai-se no parsing do README. É daí que vem a autoria confiável de cada trilha.

PRD · leg 02
spec.md · solução

O destino

O módulo tracks agrega os conteúdos 4noobs, sincronizados via GitHub, e os exibe como trilhas navegáveis com módulos e aulas — lendo e apoiando o criador sem sair da plataforma. Três princípios guiam cada decisão:

Valorizar criadores

Cada trilha tem owner e contribuidores identificáveis, com apoio real no GitHub — estrela, watch, follow, sponsor — acionado pela conta do usuário logado.

Não sobrecarregar a UI

Descoberta, leitura e interação em fluxos limpos: grid que se escaneia, leitor focado, ações compactas no header e no aside.

Preparar o futuro

Modelo com source_type de fonte única (github hoje; nativo reservado em docs) e eventos de domínio prontos para quem quiser escutar (atividade, gamificação) — sem vocabulário de recompensa no conteúdo.

PRD · leg 04
spec.md · fora de escopo

O que fica fora desta trilha

Estado pessoal do aluno — progresso, bookmark, avaliação e feedback por aula (escopo LMS removido).
Feedback de trilha, módulo e aula (útil / desatualizada) sem poluir as issues do GitHub.
Páginas dedicadas para cada trilha e seus módulos, à medida que novos metadados forem coletados.
Gamificação (XP, badges, streaks, ranking) — esforço futuro separado; tracks emite fatos e gamificação decide (E-D6).
CRUD de tracks nativas — fora; source_type tem só github hoje (E-D10), nativo é reservado em docs.
Comentários/issues via plataforma — descartado pelo risco de poluir os repositórios.
Timeline e perfil — como trilhas aparecem no perfil e na timeline fica para um esforço posterior.

System design · leg 02
docs/adr/0003

Modelo de dados

Escolha central: sem tabelas polimórficas separadas. Discriminador source_type (enum único github hoje; native reservado em docs — E-D10) + metadados de fonte em colunas planas (repo_owner, repo_name, repo_url, default_branch, language, category, stars/forks/watchers) — sem source_data JSONB (flatten do agregador, E-D11) e sem JOINs opcionais nem migrações por nova fonte. Módulos e aulas usam UUID v5 determinístico (namespace da track + path): renomear um path muda o UUID e o registro antigo ganha replaced_by_uuid. Interações de usuário sempre amarram ao UUID, nunca ao path.

Banco

Interações GitHub

AçãoEndpoints RESTScope OAuth necessário

WatchPUT /DELETE /subscription · GET checkcoberto por public_repo
SeguirPUT /DELETE /following/{username} · GET checkuser:follow (a adicionar)

Os scopes atuais do OAuth (read:user, user:email) são insuficientes — public_repo e user:follow precisam ser adicionados. Token OAuth por requisição, recuperado de ExternalIdentity, no padrão GetCurrentUser.

EstadoComportamento

Posição: header da track (Star + contagem, Watch + contagem, Sponsor, Share — compactos) e, após o conteúdo, a seção de contribuidores com Follow por contribuidor.

LessonReader

Sidebar fina colapsável com índice h2, breadcrumb, conteúdo tipado (parágrafo, h2/h3, lista, code com copy, callout, tabela), prev/next.

Interações

eventos Livewire

Estrelar/watch sincronizados entre listagem e aside via tracks-page.*/tracks-aside.*. Interações são stateless — o estado exibido é verificado contra a API; sem estado local ("salvar") e sem XP/streak.
